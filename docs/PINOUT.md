# Распиновка nice!nano v2 (nRF52840)

Таблица составлена по результатам прозвонки скетчем [`tools/pin_scan`](../tools/pin_scan/pin_scan.ino): таблица всех пинов ядра плюс замыкание каждой колодки на GND.
**Дата:** ноябрь 2026 · **Плата:** nice!nano v2 или совместимый клон (на плате есть площадки B+/B−) · **Ядро:** Adafruit nRF52, 35 пинов.

## Как читать

- **Пин на плате** — надпись на колодке (`006`, `115`…). Совпадает с именем порта: `115` = P1.15.
- **Порт** — реальный вывод nRF52840.
- **`pinMode()`** — число, которое нужно передавать в `pinMode()`, `digitalRead()`, `analogRead()`. Это номер из таблицы ядра, он **не совпадает** ни с надписью, ни с номером порта.

### Пины без номера (⚠️)

P1.00, P1.04, P1.06, P1.11, P1.13 (а также, по-видимому, P1.01 и P1.07) физически выведены на плату, но **отсутствуют в таблице пинов ядра** (`g_ADigitalPinMap`), поэтому через `pinMode()` недоступны. Это не неисправность платы. Теоретически их можно использовать напрямую через `nrf_gpio_*` и `NRF_GPIO_PIN_MAP(1, 13)` — **не проверено**.

## Схема

```
        nice!nano v2
        ┌──────────────┐
        │   USB-C      │
        └──────────────┘

ЛЕВАЯ СТОРОНА                    ПРАВАЯ СТОРОНА
(сверху вниз)                    (сверху вниз)

B−                               B+
006  → 11  ✅                    RAW
008  → 12  ✅                    GND
GND                              RST
GND                              VCC
017  → 29  ✅                    031  → 21  ✅ ADC
020  → 28  ✅                    029  → 20  ✅ ADC ⭐
022  → 30  ✅                    002  → 18  ✅ ADC
024  → 1   ✅                    115  → 3   ✅
100  — нет номера                113  — нет номера
011  → 23  ✅                    111  — нет номера
104  — нет номера               010  → 2   ✅
106  — нет номера               009  → 33  ✅
```

## Что было неверно в прежней версии таблицы

- **009** считался нерабочим под номером 16, а **113** под номером 15. Но 16 — это P0.30, а 15 — это P0.05: внутренние пины, не выведенные на эти колодки. Правильный номер для 009 — **33**. Отметки «ADC ✅» у этих двух строк относились к настоящим аналоговым пинам P0.30 (AIN6) и P0.05 (AIN3), которые на колодки не выведены.
- **P1.02** считался недоступным без регистров — на самом деле это обычный `pinMode(7, ...)`.
- Колонка «Arduino D» (D0–D21) удалена: в ядре такой нумерации нет, она только путала.
- **ADC** есть только у P0.02, P0.29, P0.31 (каналы AIN0, AIN5, AIN7): аналоговые входы nRF52840 — AIN0–AIN7 = P0.02–P0.05 и P0.28–P0.31. У порта P1 ADC нет.

## Внутренние пины (не выведены на колодки)

| `pinMode()` | Порт | Назначение |
|---|---|---|
| 14 | P0.04 (AIN2) | **измерение батареи** |
| 15 | P0.05 (AIN3) | внутренний |
| 16 | P0.30 (AIN6) | внутренний |
| 17 | P0.28 (AIN4) | внутренний |
| 19 | P0.03 (AIN1) | внутренний |
| 24 | P0.15 | синий светодиод (читается как LOW, в scan = IGNORED) |
| 25 | P0.13 | **управление питанием VCC** (см. ниже) |

Остальные номера таблицы ядра (0, 4, 5, 6, 8, 9, 10, 13, 22, 26, 27, 31, 32, 34) на колодки не выведены и не проверялись.

### ⚠️ P0.13 (pinMode 25) — не трогать

На этом пине HIGH отключает питание вывода VCC (3,3 В): потенциометр и всё, что к нему подключено, останется без питания. Прошивка этот пин не использует. В `pin_scan` он включается только как вход с подтяжкой.

## ADC

- По умолчанию (10 бит, референс 3,6 В) при питании 3,3 В максимум ≈ **938**: 3,3 / 3,6 × 1023. Для процентов: `map(value, 0, 938, 0, 100)`.
- `analogReference()` и `analogReadResolution()` глобальны и влияют на все каналы.

## Батарея

Напряжение батареи читается с **P0.04 (`pinMode(14)`)**. Коэффициент делителя зависит от конкретной платы: оригинальный nice!nano v2 и клоны устроены по-разному, поэтому в прошивке `VBAT_DIVIDER` нужно **откалибровать по мультиметру** (инструкция в комментарии у константы). Макрос ядра `PIN_VBAT` использовать нельзя: в раскладке Feather он указывает на P0.29 (пин потенциометра).
